**Four runtime uses of Shizuku.** Beyond the one-time grant, Shizuku is used at runtime in exactly four optional places, each through Shizuku's privileged process: the **no-Location Wi-Fi SSID** context runs `cmd wifi status` so Wi-Fi-based context rules can read the SSID *without* the Location permission, the **global force-dark** toggle sets the `debug.hwui.force_dark` system property (which isn't reachable through secure settings), the **Night Light temperature** is also sent to the display service on devices (such as OxygenOS) that ignore the temperature setting, once Tideo has seen the device ignore it, and while a profile's **Go beyond temperature limits** option is on, which widens the range to 686–7308 K whatever the device's own limits are (and once more just after it, so the display leaves the wider range), and the **display brightness readout** runs `dumpsys display` while Android's Adaptive Brightness is in control and during a display calibration, so Tideo can show the brightness Android chose, above 255 when High Brightness Mode boosts it; Tideo first tries the DUMP permission, then root, then Shizuku, keeps using whichever answered while it keeps answering, and only the brightness lines leave Shizuku's process. Once one of these has used Shizuku, its small helper process stays running until Tideo's own process ends, so back-to-back uses do not wait for a new one to start.
